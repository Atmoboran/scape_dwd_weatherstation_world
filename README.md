# Meteo Instrument Walk

A first-person, walk-around 3D scene (Three.js, no build step) that loads DWD
meteorological-instrument models, originally CAD `.step` files, converted and
compressed for smartphone browsers. See [`PLAN.md`](PLAN.md) for full design
rationale and remaining open items.

## Controls

**Mobile:** an on-screen joystick sits bottom-left (drag to walk, it re-centres wherever
your thumb lands), the right half of the screen is drag-to-look, `RUN` toggles sprint,
and the `Inspect` prompt opens a station's info card when you're close enough.

**Desktop:** `WASD` / arrow keys to walk, mouse to look (click to capture the pointer,
`Esc` to release), `Shift` to run, `E` to inspect a station.

Both input schemes are always live, so a touch laptop works either way. The start screen
shows the right control list for the device you're on.

## The walk

The eight stations stand in one packed row along a gravel walkway. Each has a coloured
beacon and a floating nameplate; walking up to one logs it (`stations found` counter,
top-left), and the minimap top-right shows which ones you've still got to visit - hollow
dots are unvisited, filled dots are logged. Inspecting a station opens a card with what
it is and what it measures.

## Running locally

Static files only, so any static file server works:

```bash
python3 -m http.server 8000
# open http://localhost:8000/index.html
```

## Repo layout

- `index.html`, `src/` — the app itself (vanilla Three.js, ES modules via import map).
- `assets/vendor/three/` — self-hosted Three.js build + GLTFLoader/DRACOLoader/
  PointerLockControls + the Draco decoder WASM (not loaded from a CDN, so the
  deployed site has no runtime dependency on a third party staying up).
- `assets/models/*.glb` — raw STEP→GLB conversions (no material/texture data
  survived the source STEPs).
- `assets/models/low/`, `assets/models/high/` — Draco-compressed LOD tiers
  generated by `tools/optimize_glb.sh` (low = decimated, loaded up front;
  high = full detail, lazy-loaded within 15m and disposed again past 20m).
- `assets/models/manifest.json` — generated by `tools/generate_manifest.py`;
  hand-edit `position` / `rotationY` / `scale` / `description` / `measures` per
  instrument here to fine-tune the world and its exhibit text without touching code.
- `tools/step_to_glb.py` — offline STEP → GLB conversion (OpenCASCADE via
  `cadquery-ocp`). Never run in the browser; `.step` files are not committed.
- `tools/optimize_glb.sh` — runs the `gltf-transform` LOD/compression pipeline.
- `tools/generate_manifest.py` — (re)generates `manifest.json` from the
  optimized GLBs.

## Regenerating the models

```bash
python3 tools/step_to_glb.py <input.step> <output.glb>   # per source file, see script
bash tools/optimize_glb.sh                                 # -> assets/models/low|high/*.glb
python3 tools/generate_manifest.py                          # -> assets/models/manifest.json
```

## Known open items (see PLAN.md for detail)

- `03 Windprofiler_Dio v24.step` (238MB) has not been converted yet - it's
  much larger than the others and needs its own tessellation/perf pass.
- Per-instrument `scale` in `manifest.json` is a **placeholder** (each model's
  largest bbox dimension is normalized to 3m) because the source STEPs carry
  no reliable unit metadata - calibrate against each instrument's real
  dimensions before treating distances/scale in the scene as accurate.
- No textures/materials survived the source STEPs, so each station is rendered with a
  faint per-station accent tint and flat shading rather than real CAD appearance data.
- The `description` / `measures` exhibit texts in `manifest.json` are placeholder copy
  written from the model names - review them against the real site documentation before
  treating them as authoritative.
- Deployed only as static files here; wire up GitHub Pages under
  Settings -> Pages -> Deploy from branch when ready to host.

## Deploying to GitHub Pages

Settings -> Pages -> Deploy from branch -> `main` / `/ (root)`. No build step
is required - `index.html` at the repo root is the entry point.
